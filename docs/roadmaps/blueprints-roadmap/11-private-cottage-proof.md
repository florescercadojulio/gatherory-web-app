# Private authoring and independent Cottage copies

Implemented locally October 15, 2026. This is private workspace-owned reuse,
not public/unlisted publishing, QR distribution, billing or a native editor.

## Try the development fixtures

1. Apply the initial blueprint migration and the additive private-authoring
   migration `20261015152051_loose_owl` to the intended development database.
2. If intentionally resetting development data, run the existing `pnpm db:seed`.
   **This command resets database data.** It was not run against the user's
   development or production database during implementation.
3. Sign in using the existing App Review development account. Web **Templates**
   contains **Family Cottage Stay** (published) and **Family Cottage Stay — Editing
   Draft** (unpublished), owned by App Review's personal workspace. Other seeded
   users cannot see these private templates unless granted workspace ownership.
4. On iOS using the same account and server, open **Explore**, search **Cottage**
   (or browse Events), review the published template, choose dates/time zone and
   selections, explicitly confirm child dates, and install.
5. Return to Explore and install the same published template again for different
   dates/name. A new setup submission has a new request ID; retrying an uncertain
   submission retains its original ID. Expect two independent workspaces, each
   with its own direct-child events, ideas and guides.
6. Edit an idea/date in the first copy, save/relaunch, and confirm the second copy
   is unchanged. Publishing a new source revision also must not update either copy.

The cottage has three optional activities: arrival, shared day and departure.
The departure date is an illustrative `main_start + 3 days` proposal, not a new
checkout anchor or inferred booking length. All dates still require confirmation.
Guidance is plain text; there are no actual checklist states or reminders.

## Seed organization

- `scripts/seed/development-users.ts`: existing deterministic account definitions.
- `src/db/seeds/cottage-template.ts`: portable cottage content only; no database
  or auth initialization and no public curated-catalog registration.
- `src/db/seeds/private-templates.ts`: stable request IDs, private draft creation
  and explicit publication through the same Effect workflows as the web UI.
- `src/db/seeds/curated-blueprints.ts`: explicit catalog restoration after the
  development reset, without adding private fixtures to the public starter array.
- `src/db/seed.ts`: orchestration of reset, existing event/native fixtures,
  curated catalog and App Review private template fixtures. Existing event
  hierarchy, roles and canonical/native transaction boundaries remain intact.

The standalone `blueprints:seed` deployment command still seeds only curated
Wedding, Birthday Party and Thanksgiving. It does not create test accounts or
private cottages. No import or HTTP request seeds content automatically.

## Data and authorization boundaries

Private draft CRUD is authorized against owner membership of the explicit owner
workspace—not the active session organization, team membership or event role.
The private native catalog, preview, schedule and installer use that same source
boundary. No source authorization grants access to copied events.

Create requests are idempotent per actor/request UUID. Save uses a locked draft
version comparison. Publication snapshots one saved version in a SQL transaction;
the `(templateId, draftVersion)` unique key prevents duplicate revisions.
The database immutability trigger protects source content, identity, description,
locale and publication lineage. Retiring a template blocks new installs and pending
completion but does not remove installed plans or their completed receipts.

An installed copy keeps its own stable manifest, organization/scope IDs and
native projection. Better Auth provisioning stays outside the Effect transaction;
canonical/native records and the completion receipt commit atomically. Native
runtime persistence/outbox/merge code was not changed for this slice.

## Verification and remaining gates

The non-UI tests cover private access, source copying, optimistic save conflicts,
publication retries/immutability, retirement, source revocation, and atomic
installation recovery. PostgreSQL tests run only against an explicitly opted-in
local disposable database. The two-copy fixture is generated by the real pure
planner/native projection and shared byte-for-byte with Swift tests. Native
coordinator tests exercise sequential installation, bootstrap, no-op saves,
scope-isolated offline edits, on-disk relaunch and completed-request recovery.

October 15 verification: the full web suite passed **352 tests** (15 opt-in or
environment-dependent cases skipped); both dedicated PostgreSQL installation
and private-authoring integration tests passed separately against a disposable,
freshly migrated PostgreSQL 18 database. The full non-UI native suite passed
**376 tests / 450 executions**, with zero failures/skips on iPhone 17 / iOS 27.
Native result bundle: `/tmp/gatherory-cottage-20261015-b.xcresult`.
The shared two-copy fixture files match byte-for-byte. Anonymous web template
navigation redirects to sign-in; the native catalog rejects anonymous access
with HTTP 401 and private/no-store caching.

No UI tests or web production build were run. Manual authenticated web visual
acceptance, real-device installation, deployment, and actual iOS 26 execution
remain open. This is not a claim that the full blueprint roadmap has shipped.
Author-controlled default inclusion, selectable authored locale, rich place/link
configuration and live guide editing are not added by this bounded editor.
Current publications use `en`; consumers choose their own inclusion and dates.
